# lingdiff API

A thin, read-only HTTP API over the same precomputed comparison data the
[lingdiff](https://dahrs.github.io/lingdiff/) site itself uses — send it two language codes,
get back the full scored comparison (family distance, phonology, word order, morphology,
writing system, vocabulary origin) as JSON.

Deployed and developed **separately** from the `pipeline/` package at the repo root: this
needs only `fastapi`/`uvicorn`/`pydantic`, none of `pipeline/`'s heavier dependencies
(`pycldf`, `lang2vec`, `panphon`, ...), and reads the pipeline's *output*
(`../docs/data/`) directly as plain JSON rather than importing `pipeline.schema`. Its own
`pyproject.toml`/`.venv` reflect that — same reasoning as this project's own `pipeline`
venv being separate from, say, a frontend toolchain, just one level further.

## Run locally

```
cd api
uv sync
uv run uvicorn app.main:app --reload
```

Then: `curl "http://127.0.0.1:8000/compare?a=fra&b=ita"`. Interactive docs at
`http://127.0.0.1:8000/docs` (auto-generated by FastAPI from `app/schemas.py`).

## Endpoints

- `GET /compare?a=<code>&b=<code>` — full comparison. `a`/`b` each accept an ISO 639-3 code
  (e.g. `fra`) or a glottocode (e.g. `stan1290`); the three hand-picked family/macrolanguage
  "group" entities (Romance, Italic, Arabic) only have a glottocode (`roma1334`, `ital1284`,
  `arab1395`), since they're not real ISO 639-3 languages. 404 if either code doesn't match
  anything in the dataset.
- `GET /health` — liveness check.

## Code layout

- `app/data_loader.py` — resolves a code to a profile and caches it; reads straight from
  `../docs/data/`, no network calls.
- `app/diff.py` — the actual comparison logic. **A hand-maintained Python port of
  `docs/compare.js`** — see that file's module docstring. If you change the comparison logic
  in one, change it in the other.
- `app/schemas.py` — the Pydantic response models (and therefore the OpenAPI schema at
  `/openapi.json`).
- `app/main.py` — the FastAPI app and its one route.

## Deploying

Not deployed anywhere yet — this is the application code only. Any host that can run a
Python ASGI app works (a plain VM with `uvicorn`/`gunicorn`, Fly.io, Render, Railway, ...); it
needs read access to `../docs/data/` (the two directories can be deployed together, or
`docs/data/` can be synced/mounted separately) and no secrets or external services of any
kind — the whole thing is a pure function over already-public, already-committed JSON.
